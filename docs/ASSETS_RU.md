
# Замена примитивов на графику команды

Эта инструкция описывает реально используемые поля версии 0.3, а не проект будущего API.
Все ресурсы загружаются локально из public/. Готовая автономная сборка содержит их копию
в standalone/. Изменяйте исходники в public/, затем выполняйте npm run build:standalone.
Во время npm run dev пересборка автономной копии не нужна: обновите страницу.

## 1. Один спрайт: минимальный пример

Положите два прозрачных PNG:
```
public/assets/sprites/coal-off.png
public/assets/sprites/coal-on.png
```

В `public/data/assets.json` замените запись `sprites.coal`:
```json
{
  "idle": "assets/sprites/coal-off.png",
  "powered": "assets/sprites/coal-on.png",
  "width": 58.88,
  "height": 54.4,
  "anchorX": 0.5,
  "anchorY": 0.5
}
```

В пути НЕ пишется public/. Не переименовывайте PNG в SVG: меняйте расширение в манифесте.
PNG может иметь 256×256 или 512×512 пикселей; width/height — логический размер иконки
на эталонной карте шириной 1280, а не размер исходного файла. Для первой замены оставьте
текущие width/height, чтобы ничего не сместить и не перекрыть.

anchorX/anchorY задают точку на изображении, совпадающую с координатой здания.
(0.5,0.5) — середина, (0.5,0.8) — точка ближе к нижнему основанию.
Геометрия обоих состояний должна совпадать. Прозрачные поля не обрезать по-разному.

Ключи типов: `coal`, `peat`, `hydro`, `pole`, `transformer`, `village`, `city`, `factory`.

Размеры строительной площадки для запрета перекрытия находятся в balance.json:
`buildings.<тип>.widthM / heightM`. Это условная зона размещения иконки.
Размер картинки сам по себе не меняет мощность, длину кабеля или физический размер объекта.
При значительном увеличении картинки увеличьте и площадку, иначе визуальный рисунок может
вылезать за проверяемый контур.

Отдельные вход/выход трансформатора в этой версии фиксированы: слева ВН, справа НН,
на 43% ширины его площадки от центра. Расположите рисунок так, чтобы соответствовать
цветным портам, или измените `World.endpointPosition()` в src/model/world.ts.
Модель кабеля всё равно измеряет расстояние между ЦЕНТРАМИ зданий.
ГЭС проверяет попадание в реку центральной точкой здания, а не всем рисунком плотины.

## 2. Иконки нижнего дока

Без специального файла используется основной спрайт.
Для собственного изображения добавьте необязательное поле:
```json
"icon": "assets/ui/coal-icon.png"
```
Остальные поля объекта спрайта сохраните. Подойдёт PNG 128×128 с прозрачностью.
Не рисуйте цену, название, цифру горячей клавиши и рамку выделения внутри PNG:
это отдельный UI, связанный с балансом.

## 3. Покадровая анимация зданий

Добавьте `frames` к записи спрайта:
```json
{
  "idle": "assets/sprites/coal-off.png",
  "powered": "assets/sprites/coal-working-sheet.png",
  "width": 58.88,
  "height": 54.4,
  "anchorX": 0.5,
  "anchorY": 0.5,
  "frames": { "width": 256, "height": 256, "count": 6, "fps": 8 }
}
```

powered — лист с регулярными ячейками 256×256, например 1536×256 или 768×512.
Кадры читаются слева направо, затем сверху вниз.
idle может быть одной ячейкой 256×256: в неактивном состоянии читается только нулевой кадр.
Для состояний и кадров одинаковые габариты, основание и прозрачные поля.
Для дока при анимации автоматически используется первый кадр; поле icon может его заменить.
Произвольно обрезанный/упакованный атлас JSON в этой версии не поддерживается:
сначала используйте регулярный spritesheet либо добавьте атласный загрузчик.

Активность: населённый пункт/завод обеспечен полностью; станция реально генерирует;
трансформатор передаёт мощность. Анимация декоративная и не меняет расчёт.
Простые SVG-примитивы в комплекте не содержат настоящих кадров анимации — смените их листами.

## 4. Главное меню

В assets.json есть независимый раздел:
```json
"menu": {
  "background": "assets/menu/background.png",
  "showNetworkOverlay": false,
  "layers": [
    {
      "image": "assets/menu/smoke.png",
      "amplitudeX": 8,
      "amplitudeY": 3,
      "periodMs": 8000,
      "opacity": 0.4
    }
  ]
}
```

background и все прозрачные layers — общий холст 16:10, например 2560×1600.
Слои плавно смещаются на заданное число экранных пикселей. Фон слегка масштабируется.
showNetworkOverlay:false убирает демонстрационные линии и здания поверх меню.
Название и кнопка остаются HTML-элементами. Для художественного логотипа измените
меню в App.renderUI(), а не в модель электросети.

## 5. Страница комикса

`public/data/intro.json` содержит общий размер, время проявления и панели.
Текущие панели обрезаны до своих прямоугольников:
```json
{
  "width": 1280,
  "height": 800,
  "fadeMs": 600,
  "panels": [
    {
      "image": "assets/intro/panel-01.png",
      "caption": "Страна ждёт света.",
      "x": 32, "y": 32, "width": 460, "height": 300
    }
  ]
}
```
Порядок записей = порядок появления. Уже показанные панели остаются.
caption выводится кодом на нижней плашке. Чтобы запечь надпись в рисунок, оставьте caption пустым;
пустая подпись не должна требовать дополнительного текста. Не дублируйте реплику двумя способами.

Для полностраничных прозрачных PNG возможно задать всем панелям x=0,y=0,width=1280,height=800.
В таком случае каждая картинка должна иметь прозрачность ВНЕ своей панели.
Добавьте `"fullPageLayers": true` на верхнем уровне intro.json.
В этом режиме изображения накапливаются, пустые фоны и рамки не рисуются.
Пустое поле caption полностью убирает нижнюю текстовую плашку.
Это явный параметр, а не автоматическое распознавание содержимого PNG.

Исходники художника можно делать 2560×1600: логические координаты останутся 1280×800.
Все кадры одной страницы должны совпадать по геометрии.

## 6. Карта страны

`assets.json → country.dark / country.light`.
Обе картинки одного размера и с одинаковыми очертаниями; никаких геометрических сдвигов.
Названия городов и кликабельные точки не рисовать в фоне — их выводит интерфейс.

`public/data/regions/<id>.json → city.u / city.v`: нормализованные координаты подписи.
u=x/ширина, v=y/высота, левый верхний угол — (0,0).

`countryMask` каждого региона — PNG ПОЛНОГО размера карты:
внутри региона альфа 255, снаружи 0. Не используйте непрозрачный чёрный фон.
Светлая карта компонуется с альфа-маской. Маски не должны закрывать соседние области.
Временные маски здесь схематичны; замените их настоящими контурами команды.

## 7. Игровая карта региона

Для каждого `public/data/regions/<id>.json`:
- `map`: фон без населённых пунктов, заводов и изменяемых построек.
- `masks.water`: вся открытая вода.
- `masks.hydro`: допустимые точки центра ГЭС.
- `masks.blocked`: необязательный дополнительный запрет строительства.
- `masks.spawn`: необязательные разрешённые центры появления потребителей.

Для логических масок: непрозрачный PNG, чёрный 0 = нет признака, белый 255 = есть.
Все маски должны точно совпадать по размеру и положению с фоном.
JPEG, сглаживание, полупрозрачные края и подписи не использовать.
Болото с торфом НЕ обозначать автоматически как открытую воду.

water и blocked проверяются по ВСЕЙ строительной площадке, а не только центру.
hydro проверяется по центральной точке ГЭС; вода под остальной частью плотины допустима.
spawn определяет центр появления, но вода/blocked и пересечения дополнительно проверяются по площадке.

Если маски указаны, они являются источником правил. `river.points` — геометрический резерв
для карт БЕЗ масок и для тестов; он не переопределяет PNG.
Чтобы убрать реку, передайте чёрные water/hydro-маски; не оставляйте старую геометрию
с удалённой картинкой реки и одновременно отсутствующими масками.

## 8. Месторождения и случайное появление

```json
{
  "id": "coal-a",
  "kind": "coal",
  "u": 0.17,
  "v": 0.28,
  "radiusM": 1250
}
```
kind — coal или peat. Центр станции должен оказаться внутри окружности; площадка должна
оставаться допустимой по воде и запретам. Вокруг зоны автоматически рисуется окружность.
Ресурсные фактуры можно нарисовать на фоне; технические радиусы там запекать не нужно.

`spawn.settlements`: элементы kind=city/village, u, v, name.
`spawn.factories`: u, v, name.
`spawn.jitterM`: случайное смещение вокруг подготовленных точек.
`seed`: число для воспроизводимой генерации данного региона.

Для хакатона рекомендую оставлять подготовленные точки, а не случайно распределять их
по всей области. Избегайте верхних 15% и нижних 25% карты для обязательных потребителей:
там располагается интерфейс. В комплекте две фабрики поставлены выше дока.

У карты мира физический размер задаётся в balance.json, а не пиксельными размерами PNG.
При замене 1280×800 на 2560×1600 длины линий не изменятся.
Масштаб по умолчанию — 20 км по ширине.

## 9. Портрет, реплики и оформление

`assets.json → overseer`: прозрачный PNG, например 512×512.
`public/data/messages.json`: обычные сообщения, срочное, при выполненном плане,
период и длительность показа. Не нужно редактировать TypeScript для смены реплик.

Палитра, рамки, типографика и размеры панелей — `src/style.css`.
Динамические подписи, деньги, даты и шкала времени рисуются кодом.
Статическая текстура UI целиком не используется: это мешало бы адаптации окна.
Для фона отдельного элемента можно задать CSS background-image из public/assets/ui/.

Сторонние шрифты не включены. При выборе своего шрифта обеспечьте кириллицу и право
на включение в веб-игру; файлы передаёт команда из разрешённого источника.

## 10. Проверка после замены

```bash
npm run check:assets
npm run check:native
npm run dev
```
Проверьте Network и Console браузера, оба состояния зданий, подписи городов, все маски,
масштаб камеры, выделение портов и наложение светлой карты.
Для публикации: `npm run build` либо `npm run build:standalone`.

`check:assets` проверяет наличие всех файлов и размеры PNG/SVG, которые должны совпадать.
Соответствие содержания рисунка маске человек всё равно должен проверить визуально.
